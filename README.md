# Glucose 🩸

**🔗 Live demo: [randomtoni.github.io/glucosa-diary](https://randomtoni.github.io/glucosa-diary)**

> **📱 Preview at phone width.** This is a mobile-first PWA built for a narrow screen — in a full-width desktop browser it will look stretched and the styles won't read as intended. To see it properly, open your browser's device toolbar (`Cmd`/`Ctrl` + `Shift` + `M`) and pick a phone, or narrow the window to ~390 px. Better still, open the link on your iPhone and add it to the home screen (Compartir → Agregar a inicio).

A PWA for keeping a **blood glucose diary**. Manual logging, simple and **100% offline**: everything is stored on the device (IndexedDB), with no accounts, no server and no connection.

Designed to be used from the iPhone, added to the home screen from Safari.

## Features

- **Add a reading** in one tap: value in mg/dL (20–600), date and time (defaults to now), context (Fasting, Breakfast, Lunch, Dinner) and an optional comment.
- **Edit and delete** readings (with confirmation).
- **Log** grouped by day, most recent first, color-coded by value:
  - Blue: low (`< 70`)
  - Green: in range (`70–140`)
  - Amber: elevated (`141–180`)
  - Red: high (`> 180`)
- **Line chart** (custom SVG, no libraries) with a 7 / 14 / 30 / 90-day selector and the 70–140 target band shaded.
- **Period summary**: average, minimum, maximum and % in range.
- **Export CSV** (`date, time, value_mg_dl, context, comment`) to send to your doctor.
- **Backup / restore** in JSON (full fidelity) to migrate devices or for safekeeping.
- **Daily backup reminder**: when you log the **Dinner** reading (the one that closes the day), the app offers to save a backup of the day — only once per day; later readings don't interrupt again. It's the safety net against iOS wiping your data. If you already made a backup that day, it won't ask again.
- Automatic light and dark mode, mobile-first design with large touch targets.

## Running locally

There's no build and no dependencies: they're static files. Serve the folder with any server:

```bash
# option 1 — Node
npx serve .

# option 2 — Python
python3 -m http.server 8000
```

Then open `http://localhost:3000` (serve) or `http://localhost:8000` (Python).

> A service worker needs `http(s)` or `localhost`; opening `index.html` with `file://` won't register the SW.

## Tests

The pure functions (statistics, CSV, grouping by day) live in `js/stats.js` and are tested with Node's built-in runner:

```bash
npm test        # or: node --test
```

## Regenerating the icons

The droplet PNGs are generated by code (no external assets or libraries):

```bash
npm run icons   # or: node scripts/generate-icons.mjs
```

## Deploying for free

**GitHub Pages**

1. Push the folder to a GitHub repo.
2. Settings → Pages → Branch `main` / folder `/root` → Save.
3. It's live at `https://<user>.github.io/<repo>/`.

**Netlify (drop)**

1. Go to <https://app.netlify.com/drop>.
2. Drag the project folder onto the page.
3. Done: it gives you a `https://...netlify.app` URL.

Any static host works (Cloudflare Pages, Vercel, etc.). Requirement: **HTTPS**, needed for the service worker and to install the app.

## Installing on the iPhone

1. Open the URL in **Safari** (not Chrome).
2. Tap **Share** (the square with the up arrow).
3. **Add to Home Screen**.
4. Confirm with **Add**.

It now shows up like any other app: it opens full-screen, works offline and stores the data on the phone.

> **Backups:** iOS may wipe the data of web apps that go unused for a while. The app requests persistent storage, offers to save a copy **when you log Dinner** (the close of the day, once per day) and also warns you if more than 30 days have passed without a backup. Save the JSON to iCloud/Files or email it to yourself; that keeps your data safe even if iOS clears the app.

## Structure

```
index.html          App shell
styles.css          Styles (light/dark, notch safe-area)
manifest.json       PWA manifest (standalone, icons)
sw.js               Service worker (precache + cache-first + update notice)
js/
  app.js            UI and orchestration
  db.js             IndexedDB (readings + metadata)
  stats.js          Pure functions: statistics, CSV, grouping, formatting
  chart.js          Hand-built SVG chart
icons/              Generated PNGs (192, 512, maskable, apple-touch, favicon)
scripts/
  generate-icons.mjs  Icon generator (custom PNG encoder)
test/
  stats.test.mjs    Tests for the pure functions (node --test)
```

## Privacy

The data **never leaves the device**. There's no analytics, no network, no third parties. Exporting CSV/JSON is the only way information leaves, and always by a manual action of yours (share or download).
